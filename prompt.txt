1.3 AUTHENTICATION FLOW
-----------------------
Step 1: POST username+password to login.php
Step 2: login.php calls $Security->ValidateUser($usr, $pwd, FALSE)
Step 3: ValidateUser calls User_CustomValidate($usr, $pwd)
        [EW_USE_CUSTOM_LOGIN=TRUE]
         a. LDAP search: (uid=$usr_escaped) in
            ou=Users,dc=datapatterns,dc=co,dc=in
            [S3: RFC 4515-escaped to prevent LDAP injection]
         b. LDAP bind: $user_dn + $pwd
         c. On success: $usr = AD mail attribute (REWRITTEN - this is
            the canonical username from here on)
Step 4: Back in ValidateUser: MySQL lookup
        SELECT * FROM Resources WHERE Email = '<usr>' AND IsActive = 1
         - Found row:    session ID = Emp_no, CurrentUserName = Email
         - No row:       session ID = AD mail, default permissions
         - DB failure:   [S7] $DbError=TRUE, distinct user message
Step 5: Session established, session_regenerate_id(FALSE) [Wave 2]
Step 6: If "remember me": [S4b] opaque token written to [Token] cookie
        + server store (autologin_tokens.json)
Step 7: Subsequent visits: every page calls AutoLogin()
        [S4b] token verified against store, user row re-checked
        (IsActive=1), token rotated - NO LDAP, NO password needed
Step 8: Logout: token revoked from store, cookies cleared, session destroyed

WAVE 5 - S4b AUTO-LOGIN TOKEN REDESIGN (2026-11-21, 3 files + 1 new runtime file)
-----------------------------------------------------------------------------------
PROBLEM SOLVED:
  "Remember me" used to store the user's AD password in the browser as
  [Password] = ew_Encrypt($sPassword) - a reversible TEA copy of a live
  credential, valid 1 year, impossible to revoke server-side. S4a's
  HttpOnly only blocked XSS reads; a stolen cookie file + source tree
  (key = EW_RANDOM_KEY, committed) still yielded the AD password.

NEW MECHANISM:
  Component          Detail
  ---------          ------
  [Token] cookie     Opaque 256-bit random_bytes() hex (64 chars),
                     HttpOnly, 1-year expiry. Contains NO credential.
  Server store       pddr_portal_1v00/autologin_tokens.json
                     Per-user map: {sha256(token), expires, created}
                     Only digests stored. Auto-created, mode 0600.
                     Purges expired entries on each write.
  New functions      ew_AutoLoginTokenFilePath/Write/Verify/Rotate/
  (phpfn14.php)      Revoke/New + ew_ValidateAutoLoginToken
                     Located after ew_StdDateTime, before ew_EncryptPassword
  Auto-login path    AutoLogin(): decrypt [Username] (AD mail)
                     ew_ValidateAutoLoginToken(token, usr):
                       1. Verify token (read-only) - fail fast
                       2. Look up Resources WHERE Email=usr AND IsActive=1,
                          populate session exactly as ValidateUser does
                          (NO LDAP, NO password needed)
                       3. Rotate token - ONLY if !headers_sent()
                          (else store/cookie diverge, forced re-login)
                     No-row returns FALSE (mirrors LDAP-only path)
  Key invariant      Token keyed by AD login e-mail ($usr), NEVER
                     CurrentUserName() - the latter is Resources.Email
                     on found-row path but AD mail on no-row path,
                     would diverge from [Username] cookie
  login.php          "Remember me" writes token + [Token] cookie,
                     retires legacy [Password]. If token store
                     unavailable: no auto-login (deliberate degradation,
                     no password fallback)
  Legacy migration   Pre-S4b [Password]-only cookies still honoured
                     (no forced logout on deploy). On successful legacy
                     auto-login, user migrated to token scheme within
                     the visit (write succeeds: [Token] set, [Password]
                     cleared, [Username] re-set to AD mail)
  logout.php         ew_AutoLoginTokenRevoke($sUsername) when
                     auto-login active + clears [Token] and legacy
                     [Password]
  Concurrency        flock() best-effort/advisory only (unreliable on
                     Windows/NTFS, must never gate). Store holds
                     <=1 entry/user so races degrade to one re-login.

BEHAVIORAL DELTAS (intentional):
  - Deactivated users can no longer auto-login with stale cookies
    (IsActive=1 enforced)
  - Tokens die at logout (revoked server-side)
  - Auto-login no longer hits LDAP (1 MySQL query vs LDAP bind + MySQL)
  - "Remember me" checkbox, 1-year lifetime, HttpOnly all unchanged
  - Login/logout UX unchanged for new users
